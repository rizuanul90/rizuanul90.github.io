From QA Engineer to Cybersecurity Professional — My Journey

✍️ Rizuanul Haque 📅 May 2026 ⏱ 5 min read 🔐 Cybersecurity · Career

Where It Started

My career in tech didn't begin in a cybersecurity lab — it began in quality assurance. For over four years, I worked as a QA engineer across some demanding environments: federal healthcare systems at the Veterans Affairs, high-volume e-commerce at The Estée Lauder Companies, and industrial IoT at Wabtec Corporation. Each role taught me something different, but they all shared one thing in common — I was always the person asking "how could this break?"

That mindset, I later realized, is the same mindset that drives great security professionals. A good QA engineer and a good penetration tester are both looking for the same thing: the edge case, the unexpected input, the path no one thought to protect.

"I spent years finding ways systems could fail — before the attacker did. That's not so different from what a security engineer does every day."

The Turning Point

The turning point came during my contract at the Veterans Affairs. I was conducting API security testing on mission-critical healthcare applications — validating that sensitive patient data couldn't be accessed, tampered with, or leaked through poorly constructed endpoints. I was writing REST-Assured automation scripts that specifically targeted auth bypass scenarios and injection vulnerabilities. I realized: this isn't QA anymore. This is security testing.

That realization pushed me to formalize the transition. I enrolled in the Google Cybersecurity Professional Certificate, earned my CompTIA Security+, and started building the theoretical foundation to match the practical skills I'd already been applying without fully recognizing them.

Building the Foundation

The Google Cybersecurity Certificate gave me a structured framework — NIST, incident response lifecycle, log analysis, SIEM fundamentals. CompTIA Security+ forced me to go deeper into network security, cryptography, threat intelligence, and compliance frameworks. These weren't just checkboxes; they gave names and structure to things I'd been doing instinctively in QA.

// Skills that transferred directly from QA to Security

  • API testing → API security testing (auth bypass, injection, rate limiting)
  • SQL validation → SQL injection awareness and backend data integrity checks
  • Defect triage in Jira → Security incident tracking and vulnerability lifecycle management
  • Root cause analysis → Threat analysis and forensic investigation mindset
  • CI/CD pipeline testing → DevSecOps awareness and deployment security checks
  • Accessibility compliance (508) → Security compliance and regulatory adherence
  • Automation scripting (Java/Python) → Security automation and scripting for SOC workflows

NPower & Hands-On SOC Training

In January 2026, I joined the NPower Advanced Cybersecurity Cohort — an intensive program covering SOC fundamentals, threat hunting, log analysis, system hardening, incident response, network security, and cyber risk mitigation. This is where theory became practice.

In the lab environment, I've been running Metasploit against Metasploitable 3 VMs, performing full-scope Nmap reconnaissance, brute forcing SSH credentials, and storing results in organized workspaces. I've been writing Python scripts to automate access control tasks and analyzing network traffic in Wireshark. Every lab I complete goes directly into this portfolio — because I believe a hands-on demonstration is worth more than a bullet point on a resume.

What I'm Working Toward

My immediate goal is a SOC Analyst or Security Engineer role where I can apply my testing background in a security context — monitoring alerts, triaging incidents, validating security controls, and building automation to improve detection efficiency.

Longer term, I'm working toward my B.A.S. in Computer Science and Information Security at John Jay College of Criminal Justice, and I plan to pursue CompTIA CySA+ and eventually OSCP to deepen my offensive and defensive security skills.

"The best security professionals I've read about didn't come from a single path. They came from networking, from development, from operations. My path came from quality — and I think that's a strength."

Advice for Other Career Switchers

If you're coming from a non-traditional background and considering cybersecurity, here's what I'd tell you: your existing skills matter more than you think. The ability to think methodically, document findings clearly, work across teams, and stay persistent through ambiguous problems — those are exactly what security teams need.

Start with a foundational cert (Security+ or Google Cybersecurity). Build a home lab. Document everything you do in a portfolio. And don't wait until you feel "ready" — build in public and let the work speak for itself.
