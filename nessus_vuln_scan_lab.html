// Section 02
Advanced Scan Policy Configuration
Built a custom scan policy named "Meta2" with full port range coverage, thorough assessment mode, web application scanning, and SSH credentials for authenticated host inspection.

Scan Policy Configuration

Step 01 Create Advanced Scan Policy (Meta2)
Navigated to Resources → Policies → New Policy and selected Advanced Scan from the Policy Templates. Named the policy "Meta2" to reflect the Metasploitable 2 target. Advanced Scan allows full configuration of all discovery, assessment, and reporting parameters without pre-set recommendations.
Step 02 Discovery — Full Port Range (0-65535) + UDP
Under Discovery → Host Discovery, changed Destination Ports to 0-65535 and enabled UDP alongside TCP and ICMP. This ensures every port across both protocols is probed — a default scan only covers common ports and would miss services running on non-standard ports.
nessus policy · port config
Destination Ports : 0-65535
Ping Methods      : ARP ✓  TCP ✓  ICMP ✓  UDP ✓
Port Scan Range   : 0-65535
Network Port Scan : TCP ✓
Step 03 Assessment — Thorough Tests + Web App Scanning
Under Assessment → General, enabled Perform thorough tests. This increases detection accuracy at the cost of scan speed and potential network disruption — acceptable in a controlled lab environment. Under Web Applications, toggled Scan web applications ON to detect web-layer vulnerabilities such as the Apache Ghostcat injection found in results.
Step 04 Credentials — SSH Password Auth (msfadmin)
Under Credentials → SSH, changed Authentication Method from public key to password and entered msfadmin for both username and password. This gives Nessus authenticated access to the Metasploitable 2 host, enabling local checks for installed packages, configuration weaknesses, and service versions that are invisible to unauthenticated scans.
// SECURITY NOTE Nessus labels this field "Password (unsafe!)" because storing credentials in a scan policy creates a risk if the policy is exported or the Nessus instance is compromised. In production, SSH key-based authentication or a dedicated scan account with minimal privileges is the recommended approach.

Critical Findings
6 Critical vulnerabilities — all exploitable remotely, most leading to full system compromise without credentials.

Critical Vulnerabilities

CRITICAL
UnrealIRCd Backdoor Detection
UnrealIRCd 3.2.8.1 ships with a compiled-in backdoor that allows unauthenticated remote command execution. Any attacker who sends a specially crafted string to the IRC port gets a root shell. This is one of the most well-known Metasploitable findings and a direct path to full system compromise. Exploitable via Metasploit module exploit/unix/irc/unreal_ircd_3281_backdoor.
CVSS: 10.0 · Family: Backdoors · No auth required
CRITICAL
VNC Server 'password' Password
The VNC server running on Metasploitable 2 uses the literal password "password" — detectable and exploitable by Nessus automatically during the credentialed scan. An attacker with network access gets direct graphical desktop access to the system without needing any prior foothold.
CVSS: 10.0 · Family: Gain a shell remotely · Weak credential
CRITICAL
Canonical Ubuntu Linux SEoL (8.04.x)
Metasploitable 2 runs Ubuntu 8.04 — a version that reached End of Life in May 2013. No security patches have been issued for over a decade, meaning every vulnerability discovered since 2013 affecting this OS version is permanently unpatched on this host.
CVSS: 10.0 · Family: General · No patch available
CRITICAL
Apache Tomcat AJP Connector Request Injection (Ghostcat)
CVE-2020-1938 — a critical vulnerability in the Apache JServ Protocol (AJP) connector. Allows an unauthenticated attacker to read files from the web application and achieve remote code execution if file upload is enabled. The AJP connector (port 8009) was left exposed with no authentication.
CVSS: 9.8 · Family: Web Servers · CVE-2020-1938
CRITICAL
SSL Version 2 and 3 Protocol Detection
SSLv2 and SSLv3 are cryptographically broken protocols. SSLv3 is vulnerable to POODLE (CVE-2014-3566). Both are susceptible to MITM attacks that can decrypt traffic or inject malicious content. Multiple services on the host were found serving these deprecated protocol versions.
CVSS: 9.8 · Family: Service detection · Count: 2 instances
CRITICAL
SSL (Multiple Issues)
Nessus grouped multiple SSL/TLS misconfigurations under this finding — including expired certificates, weak cipher suites, and certificate chain issues. These create opportunities for MITM attacks and traffic decryption across any service using SSL/TLS on the host.
CVSS: — · Family: Gain a shell remotely · Count: 3 instances

High Severity Findings
4 High severity vulnerabilities — each providing meaningful access or attack surface expansion to an attacker already on the network.

High Vulnerabilities

HIGH
NFS Shares World Readable
The NFS server exports file shares that are accessible to any host on the network without authentication. An attacker can mount these shares and read (or potentially write) sensitive files — a common path to credential theft or persistence.
CVSS: 7.5 · Family: RPC
HIGH
Samba Badlock Vulnerability
CVE-2016-2118 — a man-in-the-middle vulnerability in Samba's DCERPC authentication. Allows an attacker to intercept and modify Samba/Windows SMB traffic. On Metasploitable 2 the Samba version is outdated and unpatched, leaving this exploitable without elevated privileges.
CVSS: 7.5 · Family: General
HIGH
rlogin Service Detection
The rlogin service (port 513) is active — a legacy remote login protocol with no encryption and weak authentication using .rhosts trust files. An attacker can potentially log in without a password if trust relationships are misconfigured, which they are on Metasploitable 2.
CVSS: 7.5 · Family: Service detection
HIGH
rsh Service Detection
The rsh (remote shell) service is active alongside rlogin. Both protocols transmit all data in cleartext and rely on IP-based trust — making them trivially exploitable for credential theft and remote command execution on any network where the attacker can intercept or spoof traffic.
CVSS: 7.5 · Family: Service detection

Key Takeaways — Defender Perspective
What this scan revealed about the gap between "running services" and "secure infrastructure."

Defensive Analysis

Lesson 01Credentialed Scans Are Not Optional
An uncredentialed network scan of this host would have found far fewer findings. The OS End-of-Life status, installed package versions, and configuration file weaknesses are only visible once Nessus can authenticate and inspect the host internals. In enterprise environments, scan coverage without credentials is fundamentally incomplete.
Lesson 02Legacy Protocols Are Active Attack Surface
rlogin, rsh, Telnet, and SSLv2/v3 were all actively running on this host. These protocols were designed in an era before adversarial networks — they have no encryption, weak or no authentication, and well-documented exploitation paths. Their presence on any modern network is an immediate finding that requires remediation, not just documentation.
Lesson 03A Backdoor Is the Worst Possible Finding
The UnrealIRCd backdoor represents a supply chain compromise — malicious code shipped inside a legitimate software package. A defender seeing this finding in a production environment must treat it as an active incident, not a patch management task. Any host running UnrealIRCd 3.2.8.1 should be assumed compromised and isolated immediately pending forensic analysis.
Lesson 04End-of-Life OS Is a Multiplier, Not a Finding
Ubuntu 8.04 reaching EOL doesn't appear in CVSS scores — but it multiplies the impact of every other finding on the host. Every vulnerability discovered since 2013 that affects this OS is permanently unpatched. Treating EOL operating systems as just another medium finding understates the risk significantly.
