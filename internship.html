// Technical Breakdown — Packet Journey
  • 01
    User Enters a URL
    The browser cannot communicate directly with a domain name — it must first resolve it to an IP address. The packet journey begins the moment the user presses Enter.
  • 02
    DNS Resolution
    Browser checks its cache, then OS cache, then queries the recursive resolver → root DNS server → TLD server → authoritative DNS server to obtain the destination IP address.
    ⚠ Risk: DNS spoofing · Cache poisoning · DNS tunneling · C2 callbacks via DNS queries
  • 03
    TCP Three-Way Handshake
    SYN → SYN-ACK → ACK establishes a reliable connection before any data transfer. A normal handshake completes in milliseconds — hundreds of incomplete SYNs from a single source is abnormal behavior worth investigating.
    ⚠ Risk: SYN floods · Port scanning · Abnormal connection patterns
  • 04
    TLS / HTTPS Negotiation
    Server presents its certificate, browser validates it against trusted CAs, session keys are exchanged. All subsequent traffic is encrypted. Defenders cannot inspect packet contents without SSL/TLS inspection at the network boundary.
    ⚠ Risk: TLS downgrade · Certificate forgery · SSL stripping · MITM via rogue CA
  • 05
    HTTP Request & Response
    Browser sends HTTP GET with headers, cookies, and metadata. Server responds with status codes and returns HTML, CSS, JS, and other resources. DevTools demo showed 20+ subsequent requests per page load — each a monitoring opportunity.
    ⚠ Risk: Session hijacking · Suspicious user agents · Cookie theft · Directory brute-forcing via 404 bursts
  • 06
    Routing & Packet Movement
    Packets traverse routers, switches, and firewalls — each making forwarding decisions based on IP and MAC addresses. Flat networks give attackers unrestricted lateral movement. Segmentation forces traffic through monitored chokepoints.
    ⚠ Risk: ARP spoofing · BGP hijacking · Lateral movement · Rogue access points
  • 07
    Browser Renders the Webpage
    HTML, CSS, and JavaScript are assembled into the final page. Each additional resource request — scripts, fonts, APIs — generates more network activity and more opportunities for defenders to detect anomalies.

// Defender Mindset — 3 Themes
// Theme 01
Verification of Normal Behavior
Detection is impossible without a clear picture of what normal looks like. Baselines for DNS query volumes, TCP connection patterns, and HTTPS timing are the foundation of every detection capability. When a workstation suddenly generates 500 DNS queries per minute to newly registered domains, that deviation from baseline is what triggers investigation — not the traffic itself.
// Theme 02
The Strategy of Defensive Depth
A single control is a single point of failure. DNS filtering, firewalls, IDS/IPS, EDR, and SIEM each contribute different visibility at different layers. If an attacker bypasses DNS filtering, the firewall still logs the connection. If they evade the IDS signature, the SIEM correlation may still flag the pattern. Each layer compensates for the limitations of the others.
// Theme 03
Controlling the Path of Communication
Poor network design is an attacker advantage. Flat networks allow unrestricted lateral movement. Segmentation, routing controls, and firewall rules force traffic through monitored chokepoints. Honeypots inside internal segments catch reconnaissance silently — any connection to a honeypot is definitionally suspicious, generating high-fidelity alerts with very low false positive rates.

// Protocol Coverage — 8 Protocols Analyzed
  • SMB
    Server Message Block — T1021.002
    Relay attacks via LLMNR poisoning + ntlmrelayx, EternalBlue (CVE-2017-0144), Pass-the-Hash, lateral movement via PsExec/smbexec. Key insight: SMB Signing is the single most impactful control against NTLM relay. Workstation-to-workstation SMB on port 445 is rarely legitimate — alert on this pattern.
    ⚠ Detection: Event 4624 Logon Type 3, Zeek SMB logs, Impacket pipe names (svcctl, atsvc), SMBv1 traffic
  • KRB
    Kerberos — T1558.003 · T1558.001
    Kerberoasting (RC4 TGS-REQ, Event 4769), AS-REP roasting, Pass-the-Ticket, Golden Ticket (forged TGT via krbtgt hash), Silver Ticket (forged Service Ticket — bypasses KDC entirely, no DC logs generated). Fix: enforce AES256, deploy gMSA with auto-rotating passwords.
    ⚠ Detection: DC Event 4769 with TicketEncryptionType 0x17, honeypot SPN accounts, Microsoft Defender for Identity
  • NTLM
    NTLM / LLMNR / NBT-NS — T1557.001
    Responder captures NTLMv2 hashes from multicast fallback queries. ntlmrelayx relays live authentication — NO cracking needed. Attack completes in real-time from initial access to authenticated lateral movement session.
    ⚠ Detection: Event 4776 (NtLmSsp source), Zeek NTLM logs on modern OS, any host responding to LLMNR from non-DNS server
  • RDP
    Remote Desktop Protocol — T1021.001 · T1563.002
    Brute force via Crowbar/Hydra, BlueKeep (CVE-2019-0708, CVSS 9.8, pre-auth wormable RCE), RDP session hijacking via tscon.exe from SYSTEM — no password required. Shodan 2025: ~4.7M hosts with port 3389 exposed to the internet.
    ⚠ Detection: Event 4625 Logon Type 10 threshold, tscon.exe from SYSTEM or non-interactive parent, sessions at 02:00–05:00
  • DNS
    DNS — T1071.004 · T1048.003
    Tunneling via iodine/dnscat2 encodes data in subdomain labels (Base32/64). C2 beaconing with consistent query intervals. Fast-flux C2 infrastructure. DNS-over-HTTPS creates visibility blind spots — 86% of malware uses DNS for C2 (Cisco Umbrella 2024). SUNBURST used DNS beaconing via avsvmcloud[.]com.
    ⚠ Detection: dns.qry.name.len > 50, NXDOMAIN rate >20%, sustained bidirectional DNS stream to single domain, TXT queries to unknown external domains
  • WRM
    WinRM / PowerShell Remoting — T1021.006
    Pass-the-Hash via evil-winrm, lateral movement using built-in Microsoft binaries (living-off-the-land), WinRM event subscriptions for persistence. HTTP (5985) is cleartext — SOAP payloads fully visible. Without PowerShell Script Block Logging (Event 4104), WinRM-delivered commands are nearly invisible.
    ⚠ Detection: TCP 5985 from workstations, "evil-winrm" User-Agent in proxy logs, Event 4104 encoded commands
  • LDAP
    LDAP / Active Directory — T1087.002
    BloodHound maps full AD attack paths using only legitimate LDAP read operations — any domain user can run it. ACL abuse chains minor permissions (GenericWrite → AddMember → DCSync) into domain compromise without exploiting any CVE. AD CS ESC attacks via LDAP enrolment. Present in >85% of investigated intrusions (Mandiant 2024).
    ⚠ Detection: Event 4662 mass object queries from workstations, Event 2889 unsigned LDAP binds, Microsoft Defender for Identity
  • SSH
    SSH — T1021.004 · T1572
    Pivoting via -L/-R/-D flags (local forward, remote forward, SOCKS proxy). authorized_keys persistence survives password changes. SSH agent hijacking to authenticate as original user to downstream hosts. regreSSHion (CVE-2024-6387) — pre-auth RCE, patched July 2024.
    ⚠ Detection: ssh -D/-R flags in process args, new authorized_keys entries (FIM via Wazuh), sustained outbound TCP 22 from servers to external IPs
// Detection Engineering — Sigma Rules Authored
// Rule 01 · Medium
DNS Query Length Anomaly — Possible Tunneling
Detects DNS queries with query_length > 60 chars, filtering known legitimate Microsoft domains. Tagged: attack.exfiltration · T1048.003 · T1071.004. Status: experimental.
// Rule 02 · High
Kerberoasting — RC4 Service Ticket Request
Detects Event ID 4769 with TicketEncryptionType 0x17 (RC4), excluding krbtgt. Indicates offline cracking attempt against service account hashes. Tagged: attack.credential_access · T1558.003. Status: stable.
// Rule 03 · High
LLMNR / NBT-NS Poisoning Activity
Detects Event ID 4776 with LogonProcess NtLmSsp from non-computer accounts. Indicates NTLM credential capture via LLMNR poisoning. Tagged: attack.credential_access · T1557.001. Status: experimental.
// SOC Investigation Workflow Applied
// Phase 01
Alert Triage
Review SIEM/IDS alert in full — timestamp, severity, source/destination. Classify: True Positive / False Positive / Needs Investigation. Key insight: psexec.exe from a jump server at 10AM is expected; the same tool from a workstation at 2AM is an incident. Context is everything.
// Phase 02
Log Correlation
No single log source tells the full story. Correlate: DNS logs (C2 domains), proxy/HTTP logs (malicious payloads), Windows Event Logs (4624/4625/4688/4104), Firewall/NetFlow (lateral movement), EDR telemetry (process trees, memory injections), PCAP (ground truth).
// Phase 03
Timeline Reconstruction
Most impactful skill from Carnage and WebStrike labs. Sort all timestamped events chronologically to map kill chain phases. The earliest event is often the initial access vector. Example chain: T+0 DNS C2 → T+2 dropper download → T+5 PowerShell execution → T+10 LSASS dump → T+15 SMB lateral movement → T+45 data exfiltration.

// Key Takeaways
// Insight 01
Sophisticated Attackers Rarely Need Zero-Days
Week 2's central lesson: misconfigurations, weak credentials, and trusted protocols (DNS, SMB, Kerberos) are the real attack surface. BloodHound can map a path to Domain Admin using only legitimate LDAP read operations — no CVE required. The defender's advantage is visibility, baselining, and detecting the anomalies that even sophisticated attackers produce.
// Insight 02
Encryption Is Both Protection and a Blind Spot
TLS, HTTPS, DoH, SMBv3, and SSH all encrypt legitimate traffic and malicious traffic equally. Silver Tickets bypass the KDC entirely — no DC logs, only EDR catches them. DNS-over-HTTPS hides query content from network sensors. Enterprises must balance privacy with detection capability via TLS inspection and endpoint-based controls.
// Insight 03
Attacker Tools Are Often Admin Tools
PowerShell remoting, PsExec, BloodHound, and Nmap are all legitimate tools repurposed by attackers. Detection must understand context: who is running it, from where, at what time, against what target. Behavioural detection beats signature detection in living-off-the-land attack scenarios.
