// Overview

What is Wazuh?

Wazuh is an open-source security platform that provides unified XDR (Extended Detection and Response) and SIEM (Security Information and Event Management) protection for endpoints and cloud workloads. In this lab, Wazuh is installed in single-server mode on a Kali Linux VM.

ComponentPurpose
Wazuh ServerCentral component — processes alerts and manages agents
Wazuh IndexerStores and indexes security events and alerts
Wazuh DashboardWeb UI for visualizing security data and events
Universal AgentInstalled on endpoints — collects and sends security data

Wazuh Server Installation
Install all dependencies and deploy the Wazuh all-in-one installer on Kali Linux. Includes a pre-requisite step for non-Ubuntu OS environments.
// PRE-REQUISITE — Non-Ubuntu OS (Kali Linux) Before running the installer on Kali, add the Debian stable repository to your sources list:

nano /etc/apt/sources.list
Add this line: deb http://deb.debian.org/debian stable main contrib non-free
Step 01Update Your Repository
Update the Kali/Ubuntu package repository to ensure all packages are current before installing dependencies.
bash
sudo apt update
Step 02Install All Dependencies
Install the required packages that Wazuh needs to run successfully.
bash
sudo apt install vim curl apt-transport-https unzip wget \
  libcap2-bin software-properties-common lsb-release gnupg2
Step 03Download the All-in-One Installer
Download the Wazuh installation script. You can modify the version number based on the latest release notes.
bash
curl -sO https://packages.wazuh.com/4.12/wazuh-install.sh
// NOTE If you encounter hardware requirement errors, skip the hardware check using the --ignore-check parameter.
Step 04Run the Installer
Execute the all-in-one installation script. This installs the Wazuh server, indexer, and dashboard in a single command. The console output will display your admin credentials — save these immediately.
bash
sudo bash ./wazuh-install.sh -a
# Use --ignore-check if hardware requirements fail:
sudo bash ./wazuh-install.sh -a --ignore-check
// IMPORTANT — Save Your Credentials When installation completes, the console outputs your Wazuh admin username and password. These are your dashboard login credentials — copy and store them securely before closing the terminal.

Windows Agent Installation
Deploy the Wazuh agent on a Windows endpoint so it can send security telemetry back to the Wazuh server.
Step 01Navigate to Agent Deployment
In the Wazuh dashboard, go to Wazuh → Agents → Deploy New Agent.
Step 02Select Windows & Set Server IP
Select the target OS. For Windows, click MSI 32/64 bits and enter your Wazuh server's IP address in the server address field.
Step 03Copy the Deployment Command
Scroll down and copy the auto-generated PowerShell deployment command shown on the page.
Step 04Extract the MSI Download Link
From the deployment command, extract the MSI file download URL to manually download the installer.
Step 05Download & Install the MSI
Download the MSI file and install it by double-clicking. Follow the installation wizard prompts.
Step 06Configure the Agent — Set Server IP
After installation, navigate to the ossec-agent directory and edit the configuration file to point to your Wazuh server.
path
C:\Program Files (x86)\ossec-agent\ossec.conf
# Open in Notepad and set your Wazuh server IP in the <server> section
Step 07Run Services as Administrator
Open the Services panel as Administrator to manage the Wazuh agent service.
Step 08Start the Wazuh Agent Service
Start the Wazuh service. The agent will connect to the server and begin forwarding Windows security events.
// RESULT The Windows endpoint now appears in the Wazuh dashboard under Agents — sending real-time security telemetry including Windows Event Logs, file integrity monitoring, and vulnerability data.

Syslog Integration
Configure Wazuh as a syslog server and integrate a Linux endpoint (OWASP) to forward its system logs.
Step 01Configure Wazuh as a Syslog Server
In the Wazuh dashboard, navigate to Wazuh Menu → Management → Configuration to enable syslog reception.
Step 02SSH into the Linux Server (OWASP)
From your Windows machine, SSH into the target Linux server that will forward its logs.
bash
ssh user@<owasp_server_ip>
Step 03Edit the Syslog Configuration File
On the target Linux system, edit the syslog configuration file to forward logs to Wazuh.
bash
nano /etc/rsyslog.conf
Step 04Add Forwarding Rule & Restart
Add the following line at the end of the file — replace the IP with your Wazuh server IP. Save with Ctrl+X, then Y, then restart the server.
rsyslog config
*.* @<wazuh_server_ip>:514
Step 05Verify Logs in Wazuh Dashboard
In the Wazuh dashboard, use the Discover option — search for the Linux server's IP to confirm syslog messages are arriving from the OWASP server.
// RESULT Linux syslog messages from the OWASP server now appear in the Wazuh Discover view, giving defenders visibility into system events from a non-agent device.

// Part 5 of 8
Apache2 Log Forwarding via Syslog
Configure rsyslog to forward Apache2 web server access logs to Wazuh for web traffic monitoring and attack detection.
// REFERENCE https://kifarunix.com/forward-apache-logs-to-central-log-server-with-rsyslog/
Step 01Create rsyslog Configuration File
Create a dedicated rsyslog configuration file for Apache2 log forwarding.
bash
nano /etc/rsyslog.d/02-apache2.conf
Step 02 — 03Add the Forwarding Configuration
Add the following configuration to the file. This uses the imfile module to monitor Apache's access log and forward it via syslog to the Wazuh server on port 514.
rsyslog config
# Load the file input module
module(load="imfile" PollingInterval="10"
       statefile.directory="/var/spool/rsyslog")

# Monitor Apache2 access log
input(type="imfile"
      File="/var/log/apache2/access.log"
      Tag="http_access"
      Facility="local7")

# Forward to Wazuh server (replace IP with your Wazuh server IP)
local7.*    @192.168.5.190:514
Step 04Save Configuration
Save the file using Ctrl+X, then press Y and Enter to confirm.
Step 05Restart Services
Restart both rsyslog and Apache2 to apply the new configuration.
bash
service rsyslog restart
service apache2 start
Step 06Verify Logs in Wazuh
Browse to your Apache server to generate traffic, then check the Wazuh Discover option — Apache access logs tagged http_access will appear in the dashboard.
// RESULT Apache2 web server access logs are now flowing into Wazuh in real time — enabling web traffic analysis, suspicious request detection, and HTTP-based attack monitoring.

MikroTik Router — Syslog Integration
Install MikroTik RouterOS as a VM and configure it to forward all router logs to the Wazuh syslog server.
Step 01Create VM with Custom Settings
Create a new virtual machine using custom settings and map the MikroTik ISO file to the virtual DVD drive.
Step 02Select OS Type
Set the OS type to Linux and version to Other Linux 4.x Kernel in the VM settings.
Step 03Install MikroTik RouterOS
Boot the VM from the ISO. Press i to install and then Y to confirm the installation.
mikrotik console
# Press 'i' to install
i
# Press 'Y' to confirm
Y
Step 04Connect via Winbox
Open the Winbox application on Windows and click Neighbors to discover the MikroTik router — it appears with IP 0.0.0.0 initially. Click to connect.
Step 05Change Default Password
After connecting, immediately change the default admin password to a secure one.
Step 06Configure IP Address via DHCP
Navigate to IP → DHCP Client → Add an Interface. The IP address will be automatically assigned via DHCP.
Step 07Configure Syslog Forwarding to Wazuh
Configure MikroTik to send all log rules to the Wazuh syslog server.
winbox navigation
System → Logging
# Set ALL rules as: remote

Go to: Actions → Right-click "remote"
# Set Remote Address = <wazuh_server_ip>
# Click OK
// RESULT All MikroTik router logs — including routing decisions, firewall events, and connection logs — are now forwarded to Wazuh, giving defenders full visibility into network layer activity.

Web Attack Detection
Simulate SQL Injection and Cross-Site Scripting (XSS) attacks against the Apache2 web server and observe how Wazuh detects and logs them.

SQL Injection Detection

Step 01Simulate a SQL Injection Attack
Craft a URL that contains a classic SQL injection payload and send it to the Apache2 web server.
attack url
https://192.168.1.190/abc?id=admin' or '1'='1
// ATTACK EXPLAINED The payload ' or '1'='1 is a classic SQL injection that attempts to bypass authentication by making a WHERE clause always evaluate to true — potentially returning all records from a database.
Step 02Verify Detection in Wazuh
In the Wazuh dashboard, go to Discover, search for the server's IP address, and expand the log details to see the SQL injection attempt captured and classified.
// DETECTION CONFIRMED Wazuh detects the SQL injection pattern in the HTTP request URL and generates an alert — visible in the Discover view with full request details including source IP, timestamp, and payload.

Cross-Site Scripting (XSS) Detection

Step 01Simulate an XSS Attack
Craft a URL containing an XSS payload — a script tag injected into a query parameter — and send it to the Apache2 server.
attack url
https://192.168.1.190/abc?id=<script>alert(1)</script>
// ATTACK EXPLAINED This XSS payload attempts to inject a JavaScript <script> tag into the server response. If reflected back to a user's browser without sanitization, it would execute arbitrary JavaScript — potentially stealing session cookies or redirecting users.
Step 02Verify Detection in Wazuh
Return to the Wazuh Discover view, search for the server IP, and expand the log to see the XSS attempt captured with full request details.
// DETECTION CONFIRMED Wazuh identifies the script injection pattern in the HTTP request and alerts — demonstrating how SIEM platforms can detect web-based attacks from centralized log analysis without requiring agents on every web server.
